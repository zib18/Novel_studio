# Архитектура и границы первой версии

## Источник данных

Сервер хранит пользователей, сессии, романы, главы, неизменяемые редакции,
решения автора, записи библии и запреты в SQLAlchemy. SQLite предназначен
для одного локального сервера, PostgreSQL — для общей серверной установки.
Схема меняется через Alembic. Настройки и ключ API читаются только backend.

Каждая запись романа принадлежит конкретному пользователю. Проверка владельца
выполняется сервером; идентификатор из браузера не предоставляет права доступа.
Windows и Android обращаются к одному адресу сервера и одной учётной записи.

## Правки автора

Текст главы — указатель на неизменяемую редакцию. Сохранение предъявляет
base_revision_id и UUID mutation_id. Сервер меняет указатель условным UPDATE,
поэтому запоздавшая правка получает 409. Повтор доставки одной операции
идемпотентен. Восстановление прошлой версии создаёт новую редакцию.

IndexedDB хранит черновик, базовую редакцию и очередь операций отдельно для
каждого автора и главы. Ответ сохранения подтверждает снимок отправленной
операции. Новые введённые символы остаются в черновике. API не кэшируется
service worker; кэшируется только оболочка приложения.

## Канон

IDEA, PROPOSAL и UNDEFINED не являются утверждёнными фактами.
Автор отдельно принимает решение и предъявляет версию записи и canon_version.
Замена утверждённого факта создаётся предложением. Принятие фиксируется
в AuthorDecision, прежняя запись выводится из активного канона.
Удалённые ручной правкой фрагменты используются как ограничения повторной генерации.

## Задачи ИИ

API записывает Job и возвращает идентификатор; отдельный worker выполняет очередь.
Закрытие браузера не завершает worker. Статусы, результаты отдельных этапов,
отчёты, использование токенов и ошибки сохраняются в БД.
Lease и checkpoint нужны для возобновления после перезапуска.
Неизвестный результат внешнего запроса не позволяет гарантировать ровно одну
оплату; такие расходы должны учитываться как приблизительные.

Планировщик, писатель, хранитель канона, литературный редактор и корректор
вызываются отдельными Agent через OpenAI Agents SDK. Программные проверки
выполняются обычным Python независимо от литературной оценки модели.
Коммерческий редактор подключается как отдельный анализ.

Проверка не является гарантией отсутствия ошибок. Критические замечания,
неполный отчёт и исчерпанный лимит проходов показываются автору.
Результат задания — отдельный кандидат. Только команда автора применяет
его при совпадении текущей редакции и версии канона.

## Контекст длинного романа

Контекст ограничен по размеру, главы загружаются постранично.
Писателю передаются текущие факты и несколько последних глав.
Будущие секреты до установленной главы исключаются из контекста писателя.
Это базовая выборка первой версии. Семантический индекс, многоуровневые
сводки 1500 глав и полная сеть причинных связей остаются следующим этапом.

## Установка

FastAPI может обслуживать собранный frontend/dist с тем же origin.
Локальный запуск использует HTTP localhost. Для телефона и установки PWA
на внешнем устройстве нужен общий HTTPS-адрес сервера.
Capacitor использует ту же клиентскую базу; упаковка APK требует Android SDK
и отдельной проверки на устройстве.
