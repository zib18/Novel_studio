# Windows PWA и Android

Одна React/TypeScript-кодовая база, адаптивный редактор, manifest, PNG-иконки 192/512
и service worker для оболочки приложения. Тексты сохраняются в IndexedDB отдельно
для каждого владельца. Сервер хранит проекты и редакции; отдельный worker выполняет ИИ-задачи.

## PWA

Для установки на Android нужен общий HTTPS-сервер. localhost телефона относится
к самому телефону. Приложение и API должны использовать один HTTPS-origin.

Из папки frontend на Windows с Node.js 22.12 или новее:

```powershell
npm install
npm test
npm run build
```

Сборка находится в frontend/dist; её обслуживает FastAPI вместе с /api.
Запуск сервера и worker описан в корневом README. Для разработки npm run dev
проксирует API на http://127.0.0.1:8000; service worker включён только в production.

Windows Chrome/Edge: меню → «Установить Novel Studio».
Android Chrome: меню → «Добавить на главный экран» / «Установить приложение».
Кнопка установки в настройках появляется, если браузер предоставил install prompt.

## Офлайн и конфликты

После входа и открытия главы её текст сохраняется на устройстве. Перед переключением
главы или закрытием приложения дождитесь «Синхронизировано». Если переключиться раньше
отложенного сохранения, правка остаётся локально и синхронизируется при повторном открытии.

При потере ответа повторяется точный запрос с прежним UUID; поздние правки сохраняются.
При конфликте автор сравнивает обе версии и выбирает серверную либо свой объединённый текст.
До выбора локальная версия попадает в резервную историю.

Современный Chrome/Edge/Firefox использует Web Locks: одна глава редактируется в одной
вкладке данного профиля; вторая открывает её для чтения. Закройте первую и заново откройте
главу для захвата. Без Web Locks редактор показывает причину и работает для чтения.

Офлайн недоступны генерация, создание романов/глав и изменение серверного канона.
Защищайте профиль браузера. Выход сохраняет черновики, но закрывает доступ до следующего входа.
Очистка данных сайта удаляет несинхронизированные тексты; нужны синхронизация и серверные копии.

## Подготовка APK

APK здесь не собирался. Нужны Android Studio, Android SDK, JDK 21 и HTTPS-сервер.
Конфигурация Capacitor использует удалённый origin: страница и API работают с общими
cookie/CSRF. Сервер должен быть доступен. Удалённый origin не обеспечивает автономный
старт APK после очистки WebView; основной офлайн-режим первой версии — PWA.
Для bundled-сборки нужны отдельная схема авторизации/API origin/CORS и проверка оболочки.

Из корня репозитория после сборки frontend/dist:

```powershell
npm init -y
npm install --no-save @capacitor/core@7 @capacitor/cli@7 @capacitor/android@7 typescript@5.9.2
$env:NOVEL_STUDIO_ORIGIN = "https://your-novel-studio.example"
npx cap add android
npx cap sync android
npx cap open android
```

В Android Studio: Build → Generate APKs для отладочной установки.
Для распространения создайте подписанную release-сборку, не размещая ключ подписи в GitHub.
Проверьте вход, сохранение, повторное открытие, конфликты устройств и выполнение задачи
при закрытом приложении. Физическая установка PWA/APK и Tauri ещё не проверялись.
