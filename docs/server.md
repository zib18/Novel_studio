# Novel Studio: общий сервер для Windows и Android

Компьютер и Android открывают один HTTPS-адрес. PostgreSQL хранит романы,
отдельный worker выполняет ИИ-задачи даже при выключенном компьютере.
Android устанавливает PWA из Chrome.

## Что потребуется и сколько стоит

Дешёвый ориентир: Hetzner CX23, 2 CPU, 4 ГБ RAM, 40 ГБ SSD.
Сервер €5,49 + публичный IPv4 €0,50 = около €5,99/месяц до налогов.
Доступность и итоговую стоимость проверьте перед заказом.
Подойдёт другой VPS с Ubuntu 24.04, минимум 2 ГБ RAM и публичным IPv4.
OpenAI оплачивается отдельно. Для адреса можно использовать бесплатный DuckDNS.

- [Подтверждённые тарифы](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/)
- [Образ Docker CE: Ubuntu 24.04 + Docker Compose](https://docs.hetzner.com/cloud/apps/list/docker-ce/)
- [DuckDNS](https://www.duckdns.org/)

Исходники не покупают сервер и не меняют DNS. Реальный запуск и установка на
физическом Android проверяются после настройки вашего VPS.

## 1. Подготовить SSH на Windows

В обычном PowerShell, по одной команде:

~~~powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh" | Out-Null
~~~

~~~powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\novel_studio"
~~~

Можно задать пароль SSH-ключа; символы при вводе не отображаются.
Если файл уже существует, выберите другое имя вместо перезаписи.

~~~powershell
notepad "$env:USERPROFILE\.ssh\novel_studio.pub"
~~~

В кабинет хостинга добавляется содержимое файла **.pub**, открытого ключа.
Файл без .pub является приватным и остаётся на вашем компьютере.

## 2. Создать VPS и адрес

Создайте VPS с публичным IPv4 и подготовленным открытым SSH-ключом.
В Hetzner можно выбрать Apps → Docker CE: Docker и Ubuntu 24.04 уже установлены.
Сохраните IPv4 сервера.

В DuckDNS создайте свободное имя, например my-novel.duckdns.org, и укажите
IPv4 VPS. Если есть свой домен, настройте его A-запись на тот же IP.

Во внешнем firewall хостинга разрешите TCP 22, 80 и 443; UDP 443 необязателен
и используется для HTTP/3. Compose не публикует порты API и PostgreSQL.

## 3. Подключиться с Windows

Замените SERVER_IP на IPv4 VPS:

~~~powershell
ssh -i "$env:USERPROFILE\.ssh\novel_studio" root@SERVER_IP
~~~

При первом подключении сверяйте fingerprint через консоль хостинга.
После подключения строка станет Linux, например root@server:~#.

Следующие команды выполняются **на сервере**, в SSH:

~~~sh
docker --version
~~~

~~~sh
docker compose version
~~~

Если выбрана обычная Ubuntu 24.04 без Docker, сначала:

~~~sh
apt-get update
~~~

~~~sh
apt-get install -y docker.io docker-compose-v2 git
~~~

~~~sh
systemctl enable --now docker
~~~

Получите код:

~~~sh
git clone --branch novel-studio/deployment https://github.com/zib18/Novel_studio.git
~~~

~~~sh
cd Novel_studio
~~~

## 4. Создать настройки и базу

~~~sh
python3 deploy/setup.py
~~~

На первый вопрос введите только имя сайта, например my-novel.duckdns.org,
без https://. На второй вставьте новый OpenAI API-ключ; ввод скрыт.
Можно нажать Enter и подключить ИИ позднее.

Скрипт создаёт приватный .env с правами 600 и случайным паролем PostgreSQL.
Существующий .env не перезаписывается. Ключ и пароль не печатаются.
Модель и расчётные лимиты $1/задачу и $5/день меняются в этом файле.
Цены приблизительные; актуальный расход проверяется в OpenAI.

~~~sh
docker compose config --quiet
~~~

~~~sh
docker compose build api
~~~

~~~sh
docker compose up -d db
~~~

~~~sh
docker compose run --rm api python -m app.cli migrate
~~~

Теперь выберите перенос существующей Windows-базы или создание нового автора.

## 5. Перенести романы с Windows

Перенос сохраняет прежний email, пароль, UUID, канон, запреты, главы, историю,
промпты и результаты задач. Незавершённые задачи отменяются, чтобы не начать
платную генерацию самовольно. Старые сеансы не переносятся.

Целевая база должна оставаться пустой: без созданного автора и браузерных сессий.
До завершения импорта выполняйте только серверные команды, затем откройте сайт.

На Windows дождитесь «Синхронизировано» у открытых глав и закройте редактор.
Локальные черновики, ещё не дошедшие до сервера, не входят в копию базы.
Остановите локальные API/worker через Ctrl+C.

В **локальном Windows PowerShell**, из основной папки старого приложения:

~~~powershell
Push-Location backend
~~~

~~~powershell
..\.venv\Scripts\python.exe -m app.cli backup --output ..\novel-transfer.db
~~~

~~~powershell
Pop-Location
~~~

Замените SERVER_IP и загрузите штатную резервную копию прямо на VPS:

~~~powershell
scp -i "$env:USERPROFILE\.ssh\novel_studio" .\novel-transfer.db root@SERVER_IP:/root/novel-transfer.db
~~~

Файл содержит ваши тексты и аккаунт. Для него используются SSH и ваш сервер;
не публикуйте его в GitHub или переписке.

На **сервере**, в папке Novel_studio, ограничьте доступ к копии:

~~~sh
chmod 600 /root/novel-transfer.db
~~~

Импорт запускается отдельным административным контейнером, который сможет прочитать
этот закрытый файл; постоянные API и worker работают от непривилегированного пользователя.

~~~sh
docker compose run --rm --user 0:0 -v /root/novel-transfer.db:/tmp/novel-transfer.db:ro api python -m app.transfer --source /tmp/novel-transfer.db
~~~

Ожидается «Перенос завершён» и количество записей. Источник открывается только
для чтения; целевой импорт выполняется одной транзакцией. Непустая база или
несовпадение миграций приводят к отказу. Не очищайте существующие данные ради
повторного запуска. При разрыве связи во время подтверждения транзакции сначала
проверьте целевую базу.

Если существующих романов нет и нужна новая база, **вместо переноса**:

~~~sh
docker compose run --rm api python -m app.cli create-user --email author@example.com
~~~

Укажите свой адрес. Пароль вводится дважды, минимум 12 символов; ввод скрыт.

## 6. Запустить и открыть студию

С настроенным API-ключом:

~~~sh
docker compose --profile ai up -d
~~~

Для редактора без ИИ:

~~~sh
docker compose up -d
~~~

~~~sh
docker compose ps
~~~

Caddy автоматически получает HTTPS-сертификат, когда DNS указывает на VPS
и доступны входящие 80/443. Контейнеры автоматически перезапускаются.
PostgreSQL и сертификаты находятся в постоянных томах.

Диагностика:

~~~sh
docker compose logs --tail 50 api worker https
~~~

Ключ не подтверждает баланс, доступ к модели или успешную генерацию.
После изменения .env применяйте docker compose --profile ai up -d.

## 7. Android и синхронизация

Откройте один адрес https://ВАШЕ-ИМЯ.duckdns.org на компьютере и Android.
После переноса войдите прежним email/паролем; после create-user — новым аккаунтом.

Android Chrome: меню ⋮ → «Установить приложение» / «Добавить на главный экран».
Кнопка установки в Novel Studio появляется, если браузер предоставил предложение.

Проверьте:
1. Измените главу на компьютере, дождитесь «Синхронизировано», откройте на телефоне.
2. Измените строку на телефоне, дождитесь синхронизации, проверьте на компьютере.
3. Запустите пробную генерацию, закройте страницу и выключите компьютер.
   Серверный worker продолжает задачу; результат будет доступен с телефона.
4. Прочитайте текст и замечания. Применение редакции и утверждение главы —
   два отдельных решения автора.

Работайте с общей базой через новый HTTPS-адрес на обоих устройствах.
Старый localhost является отдельной локальной копией; сохраните её как резервную.

## Резервные копии и обновления

На сервере:

~~~sh
sh deploy/backup.sh
~~~

Согласованный pg_dump записывается в backups/*.dump с закрытыми правами.
Храните вторую копию на другом устройстве или в защищённом хранилище.
Обычное пересоздание контейнеров сохраняет том postgres_data.
Команда down --volumes удаляет данные и не используется для обновления.

Перед обновлением сделайте резервную копию, затем:

~~~sh
git pull --ff-only
~~~

~~~sh
docker compose --profile ai up -d --build
~~~

API применяет миграции, worker ждёт готовности схемы.

## Альтернатива: Render

render.yaml описывает управляемые web, worker и PostgreSQL: примерно $20/месяц
за вычисления плюс хранение, налоги, трафик и OpenAI. Blueprint проверяется
по официальной JSON Schema без создания платных ресурсов.

API автоматически использует RENDER_EXTERNAL_URL для HTTPS-origin и Secure-cookie.
Строка PostgreSQL нормализуется для установленного psycopg.
Ключ задаётся в кабинетах web и worker; при последующих Blueprint sync он меняется
вручную. Внешний запуск и загрузка файла в конкретный контейнер проверяются отдельно.

## Что проверяет CI

Production Docker image, настоящий HTTPS с доверенным тестовым CA, Secure/HttpOnly
cookie, CSRF, PWA-файлы, две сессии, конфликты редакций, TXT/DOCX, готовность БД
и сохранность после пересоздания API/PostgreSQL. Импорт проверяется на SQLite
и изолированных схемах настоящей PostgreSQL.

Это не подтверждает оплату хостинга, внешние DNS/сертификат вашего домена,
платный запрос OpenAI или установку на физическом Android.
