# Novel Studio

Личная студия для русскоязычных веб-новелл. React/TypeScript/Vite, FastAPI,
SQLAlchemy/Alembic, OpenAI Agents SDK. Исходники текущего рабочего блока находятся
в ветке `novel-studio/core`.

## Состояние рабочего блока

Собраны база, авторизация, романы, редакции глав, подтверждаемый канон, журнал
запретов, серверная очередь и независимые агенты. Интерфейс, offline-черновики,
PWA и проверки собраны в этой же ветке. Серверные проверки уже прошли
на Windows и Ubuntu, включая 50 тестов и HTTP-перезапуск. PostgreSQL проверен
отдельным настоящим серверным сценарием. Браузерные проверки ещё выполняются.
Это первая версия ядра, а не завершение всех двадцати разделов спецификации.

Кандидат ИИ не заменяет главу автоматически. Ручные правки сохраняются через
проверку базовой редакции; конфликт возвращает 409. Канон меняется только
отдельным решением автора. Задачи и результаты сохраняются в базе.

## Запуск на Windows

Нужны Python 3.12 и Node.js 22.12 или новее. Скачайте ZIP именно рабочей ветки
или клонируйте её:

```powershell
git clone --branch novel-studio/core https://github.com/zib18/Novel_studio.git
cd Novel_studio
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
if (-not (Test-Path backend\.env)) { Copy-Item backend\.env.example backend\.env }
```

Не перезаписывайте существующий backend/.env. Для редактора без ИИ ключ не нужен.
Для генерации откройте backend/.env локально и задайте NOVEL_OPENAI_API_KEY.
Ключ не вводится в браузер и не включается в Android-приложение.
NOVEL_OPENAI_MODEL должен обозначать модель, доступную вашему API-аккаунту.

Подготовьте базу и пользователя. Команда создания пользователя запрашивает
пароль в терминале:

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m app.cli migrate
..\.venv\Scripts\python.exe -m app.cli create-user --email author@example.com
Pop-Location
```

Укажите свой email. Публичной регистрации и учётной записи с готовым паролем нет.

Соберите интерфейс:

```powershell
Push-Location frontend
npm install
npm run build
Pop-Location
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000 и войдите. Для ИИ в **втором** терминале,
из корня того же проекта:

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m app.generation.worker
```

Оставьте оба терминала открытыми. Закрытие страницы не останавливает worker.
Ctrl+C останавливает процесс в соответствующем терминале.
После обновления исходников снова примените migrate и пересоберите frontend.

## Как пользоваться ядром

1. Создайте роман и главу. Текст сохраняется автоматически, локальный статус
   отличается от подтверждённого серверного сохранения.
2. Внесите свободные идеи или записи библии. IDEA и PROPOSAL не являются каноном.
   Подтвердите нужные факты отдельной командой; будущее событие имеет главу допуска.
3. Напишите свободное задание и запустите главу или её проверку.
4. Просмотрите кандидата, исходный/исправленный текст и отчёт с цитатами.
   Проверка по умолчанию ограничена тремя проходами.
5. Примените выбранный целый вариант и отдельно утвердите главу.
   Если глава или канон изменились, сначала разрешите конфликт.
6. История позволяет сравнить редакции и восстановить прошлую как новую.
7. Экспортируйте текущие или утверждённые главы в TXT/DOCX.

Выборочное применение отдельных фрагментов, закрепление сцен, EPUB, графы,
английская адаптация и коммерческий календарь — следующие модули.

## Windows и Android

Собранный frontend обслуживается FastAPI с тем же адресом API.
PWA устанавливается через поддерживаемый браузер на localhost либо HTTPS.
Для одного романа на компьютере и телефоне нужен **один общий HTTPS-сервер**
и одна учётная запись. localhost телефона не указывает на компьютер.

На сервере используйте PostgreSQL, HTTPS reverse proxy, NOVEL_COOKIE_SECURE=true
и явно задайте NOVEL_ALLOWED_ORIGINS для вашего домена. API и worker должны
работать постоянно. Настройка DNS/HTTPS и хостинг не выполняются исходным кодом. Для публичного
адреса ограничьте частоту входа и выдачи сессий на reverse proxy:
[пример Nginx](docs/nginx.conf.example). Backend не содержит собственного
ограничителя частоты входа; не открывайте его порт напрямую в интернет.

Черновики хранятся в IndexedDB браузера для конкретного автора и главы.
Очистка данных браузера удаляет ещё не синхронизированные локальные данные.
[Android PWA и Capacitor](docs/android.md) описывают подготовку APK.
Собранный и проверенный на устройстве APK пока не поставляется.

## Проверки

GitHub Actions: Windows/Ubuntu backend, SQLite/PostgreSQL, сборка TypeScript,
offline-очередь и Chromium с настольным/мобильным размером экрана.
Платная генерация OpenAI и физическая установка PWA/APK в CI не выполняются.

```powershell
Push-Location backend
..\.venv\Scripts\python.exe -m pytest -q
Pop-Location
.\.venv\Scripts\python.exe backend\scripts\verify_studio.py
Push-Location frontend
npm test -- --run
npm run build
Pop-Location
```

Основные Python-зависимости закреплены в requirements.txt. Транзитивные Python-
зависимости сохраняются в артефакте CI; отдельного полного lock-файла пока нет.

## Расходы и настоящий пробный запуск

Лимиты запросов, объёма контекста, токенов ответа, бюджета задачи и дневного
расхода задаются на сервере. Использование и приблизительная стоимость сохраняются.
После таймаута неизвестный результат запроса учитывается консервативно.
Актуальный расход сверяйте с кабинетом OpenAI.

## Резервные копии

Пользовательские базы, .env и backups исключены из Git.
Перед обновлением схемы сделайте резервную копию. CLI содержит backup для SQLite;
для PostgreSQL используйте pg_dump. Копии нужно хранить отдельно от рабочего сервера.
